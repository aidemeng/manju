# Episode Catalog

Use this reference for `catalog` mode. The catalog is the production bridge between the outline and individual storyboard files; it should expose continuity and cost risks before drafting begins.

## Catalog row contract

Create exactly one row per planned episode with these fields:

| Field | Meaning |
|---|---|
| Episode | Stable number with no duplicates or gaps |
| Title | Short, specific, and not a generic mood word |
| Advance | The irreversible story movement in one sentence |
| Conflict | Who or what blocks the episode objective |
| Payoff | What question, emotion, or setup is delivered now |
| End hook | The specific question opened by the final beat |
| Character change | Relationship, belief, status, or decision change |
| Continuity | Setup planted, payoff collected, or upstream fact required |
| Visual weight | Low, medium, or high production demand |

Do not repeat the outline synopsis verbatim. The catalog should be concrete enough that a writer can draft the episode without inventing a new plot.

## Hook diversity pass

Label each hook internally as one of: revelation, dilemma, promise, emotional turn, discovery, reversal, deadline, costly victory, or consequence.

Check every rolling group of five episodes:

- No adjacent episodes use the same hook family.
- At least one prior setup receives a payoff.
- No more than two episodes end before the episode-level objective changes state.
- A threat escalation is followed by a decision, discovery, or relationship consequence rather than another larger threat by default.

If repetition is found, change the dramatic function—not merely the wording.

## Production balance

Use visual weight to prevent impossible batches:

- **Low:** one location, small cast, limited effects, dialogue or discovery led.
- **Medium:** location change, controlled action, transformation detail, or moderate effects.
- **High:** crowds, large destruction, elaborate creatures, environment transformation, or multi-location climax.

A default five-episode batch should normally contain no more than two high-weight episodes. Place high-weight episodes at meaningful structural peaks, not on a fixed numerical schedule.

## Continuity pass

Before approving the catalog:

1. Check episode numbering and act boundaries.
2. Verify every payoff points to a planted setup.
3. Verify mechanism limits agree with `outline.md`.
4. Verify character changes agree with `characters.md` and do not skip required choices.
5. Check that a character's location, injuries, possessions, and knowledge can carry between adjacent episodes.
6. Flag any row that requires an unplanned new character, location, ability, or resource.

## Catalog completion check

- The row count equals the project's configured episode count.
- Titles are distinct and reveal the episode's dramatic identity.
- Each episode has one main advance and one defined payoff.
- Hooks and conflict resolutions vary across adjacent episodes.
- High-cost visuals are distributed deliberately.
- Adult and consent boundaries remain visible wherever romance is planned.
