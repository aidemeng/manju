# Manju Skill 通用化迁移设计

## 目标

将现有 `.claude` 专用漫剧创作资料包重构为仓库内的通用 Agent Skills 技能包，并兼容 Codex 的技能展示与调用机制。新技能以视觉优先的漫剧创作为默认方向，默认生成 80 集、每集 120 秒、每批 5 集，同时允许用户覆盖这些参数。

## 范围

本次迁移包含：

- 删除整个 `.claude/` 目录，不保留旧版备份。
- 在 `skills/manju-skill/` 创建新的通用技能包。
- 去除 Claude 专用命令、Claude Agent 和未实现的自动触发声明。
- 重写根目录 `README.md`，使安装与使用说明匹配新技能。
- 合并、去重现有创作方法、模板和示例。
- 统一集数、结构、分镜格式、质检维度和内容安全边界。

本次迁移不包含：

- 发布或安装到用户级技能目录。
- 提交、推送 Git 或创建发布包。
- 接入外部绘图、视频、存储或项目管理服务。
- 自动生成一部完整的 80 集作品。

## 技能结构

```text
skills/manju-skill/
├── SKILL.md
├── agents/
│   └── openai.yaml
├── references/
│   ├── story-development.md
│   ├── character-bible.md
│   ├── episode-catalog.md
│   ├── storyboard-writing.md
│   ├── quality-review.md
│   └── example.md
└── assets/
    └── templates/
        ├── project.md
        ├── outline.md
        ├── characters.md
        ├── catalog.md
        ├── episode.md
        └── review.md
```

`SKILL.md` 是唯一入口，包含标准 YAML frontmatter、任务识别、模式路由、共享约束、状态检查和输出规则。详细创作方法按任务加载对应 `references/` 文件；可复制并填写的 Markdown 骨架放入 `assets/templates/`。`agents/openai.yaml` 仅承载 Codex UI 元数据，核心工作流不依赖任何厂商专用命令。

## 调用与模式路由

技能以 `$manju-skill` 调用，也允许系统根据描述自动选择。技能支持五种工作模式：

| 模式 | 典型请求 | 读取内容 | 主要输出 |
|---|---|---|---|
| `outline` | 创建故事设定或分集大纲 | `story-development.md`、项目和大纲模板 | `project.md`、`outline.md` |
| `character` | 创建或修订角色圣经 | `character-bible.md`、角色模板 | `characters.md` |
| `catalog` | 创建分集生产索引 | `episode-catalog.md`、目录模板 | `catalog.md` |
| `write` | 编写指定集数或批次 | `storyboard-writing.md`、剧集模板 | `episodes/episode-NNN.md` |
| `review` | 质检并修订指定批次 | `quality-review.md`、质检模板 | `reviews/batch-NN.md` |

如果用户没有明确模式，技能根据请求判断。无法可靠判断时只询问一个最关键的问题。用户给出已有项目目录时优先续写，不重新生成已存在的上游文档。

## 输入与默认参数

最低必要输入为故事核心概念。创建新项目时，技能补齐或询问以下信息：

- 作品名与一句话卖点。
- 题材、目标受众和内容调性。
- 主角目标、核心能力或叙事机制。
- 美术风格和目标生成媒介。
- 内容尺度与目标平台要求。

默认参数：

- 总集数：80 集。
- 单集时长：120 秒。
- 批次大小：5 集，共 16 批。
- 画面方向：竖屏视觉优先。
- 输出语言：中文；绘图关键词可按用户需要附英文。
- 输出根目录：`manju-output/<作品名>/`，用户可覆盖。

用户明确提供的参数始终覆盖默认值。若用户只要求在聊天中展示，不写入文件。

## 故事结构

默认 80 集采用五幕结构，每幕 16 集：

1. 触发与第一次兑现：建立人物困境、故事机制和首轮回报。
2. 扩张与代价：扩大目标、关系网和规则压力。
3. 中点反转：重解释既有信息，改变主角策略。
4. 失控与重组：让旧方法失效，迫使人物承担代价并成长。
5. 终局与余波：回收核心伏笔，完成情绪兑现并留下必要余韵。

该结构是默认规划工具，不是硬编码剧情。爽点、恐惧、浪漫、谜团、牺牲、关系变化等均可承担钩子功能。禁止固定要求“每三集打脸”或“每五集擦边”；相邻剧集应避免重复同一种冲突解决和结尾钩子。

## 输出结构与状态流

```text
manju-output/<作品名>/
├── project.md
├── outline.md
├── characters.md
├── catalog.md
├── episodes/
│   ├── episode-001.md
│   └── episode-080.md
└── reviews/
    ├── batch-01.md
    └── batch-16.md
```

数据流为：

```text
项目参数 → 大纲 → 角色圣经 → 分集目录 → 单集分镜 → 批次质检 → 修订
```

写作前检查依赖：

- `character` 需要已存在的项目参数和故事方向。
- `catalog` 需要大纲与角色圣经。
- `write` 需要项目参数、大纲、角色圣经和目录。
- `review` 需要对应剧集及其上游文档。

缺失上游文件时，技能先报告缺口，并在用户请求允许的范围内创建缺失内容。已有文件默认增量更新；覆盖大段既有创作前先说明影响并获得确认。

## 分镜格式

所有单集统一使用 Markdown 表格，不再保留逐 Frame 文本块的第二套格式。每个镜头包含：

- 镜号与预估时长。
- 景别和镜头运动。
- 画面主体及稳定身份特征。
- 可见动作、表情、环境、道具和光影。
- 台词、旁白或无台词标记。
- 音效、音乐和制作备注。

默认节奏区间统一为：

- `0–15s`：异常状态、冲突或悬念切入。
- `15–60s`：建立目标、阻力和信息差。
- `60–100s`：选择、反转或视觉兑现。
- `100–120s`：结果余波与下一集钩子。

具体镜头数由动作复杂度和生成媒介决定，不强制每集 25–30 镜头。画面描述以可生成和角色连续性为目标，不机械堆满五类形容词。

## 内容安全与创作边界

- 所有参与恋爱、暧昧或性张力情节的角色必须明确为成年人。
- 禁止将未成年人或“萝莉、学生制服、等待长大”等未成年编码元素性化。
- 禁止以食物、住所、安全、工作或权力作为亲密行为交换条件。
- 禁止把胁迫、无法拒绝或明显权力失衡包装为浪漫同意。
- 暧昧是可选的张力工具，不是频率指标；可用信任、背叛、牺牲、谜团、利益冲突和价值选择替代。
- 暴力默认采用非写实、非重口的视觉表达；目标平台有更严格要求时，以平台要求为准。
- 角色不得仅作为奖品、附属物或羞辱工具；主要角色应具有独立目标、行动能力和剧情作用。

## 质量评审

每完成一个默认批次后执行一次同技能 `review`。质检使用 10 项、100 分制，每项 10 分：

1. 剧情推进。
2. 人物一致性与主动性。
3. 时间线和因果。
4. 核心机制及限制。
5. 单集节奏。
6. 视觉可生成性。
7. 钩子有效性和多样性。
8. 前后衔接与伏笔回收。
9. 制作可行性和成本密度。
10. 内容安全与目标平台适配。

评分规则：

- `90–100`：通过，可继续。
- `80–89`：通过，但记录可选优化项。
- `60–79`：需要修订后复检。
- `<60`：阻断后续批次，先修订结构性问题。
- 任意内容安全项判定为严重问题时，无论总分多少都必须修订。

质检报告必须引用具体集数和镜号，区分“必须修改”和“建议优化”。默认只修订当前批次，不擅自重写整个项目。

## 示例策略

旧版三个长示例缩减为一个跨模式的紧凑示例，展示：

- 项目输入如何转化为五幕大纲摘要。
- 一个角色如何保持视觉身份一致性并具有独立目标。
- 一集如何从目录条目转化为分镜。
- 质检如何发现重复钩子、因果缺口或机制限制冲突。

示例用于说明输出关系，不规定题材、性别视角或固定爽点。示例角色全部明确为成年人。

## README 迁移

根目录 README 将删除 Claude Code 配置步骤、`/character`、`/catalog`、`/write`、`/align`、Claude 模型和 Agent 配置说明，改为：

- 新技能目录说明。
- `$manju-skill` 调用示例。
- 五种模式示例。
- 默认 80 集和16批工作流。
- 输出目录说明。
- 通用 Agent Skills 的复制或安装提示。

## 验证策略

迁移前记录旧技能的可观察失败：缺少标准 frontmatter、无对应命令文件、60/70集冲突、三/四幕冲突、10/11项质检冲突和分镜双格式。

迁移后执行：

1. 使用 `skill-creator` 自带的 `quick_validate.py` 校验技能名、frontmatter 和占位符。
2. 检查 `SKILL.md` 中引用的所有资源均存在。
3. 扫描仓库，确保不存在 `.claude` 目录、Claude 专用命令、60/70集旧默认值和无效引用。
4. 用三个真实请求做独立前向测试：新建80集大纲、从已有项目续写一个批次、复检一个包含重复钩子的批次。
5. 检查生成结果是否遵守目录结构、依赖检查、成年角色边界和评分规则。
6. 检查 Git diff，确认没有修改范围外的文件。

不自动提交或推送任何改动。

## 成功标准

- 新技能通过结构校验并能被 `$manju-skill` 调用。
- 技能正文不包含 Claude 专用路径、命令、Agent 或模型配置。
- 默认参数在所有文件中一致为80集、120秒、5集一批、16批。
- 五种模式均有明确输入、依赖、读取资源和输出。
- 分镜只有一种规范格式。
- 质检固定为10项100分制，并有明确通过阈值。
- 所有内容安全边界在主入口和相关参考中一致。
- README 与实际目录及调用方式完全一致。
